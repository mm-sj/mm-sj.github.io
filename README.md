# 오창민 — Interactive Portfolio

도면 → 건축 모형 → 파라메트릭 파사드 → DocQ → Would You Draw → Jabis → 연락처.
스크롤을 내리면 **같은 800개의 큐브**가 장면마다 모양을 바꾸며 이야기를 이어갑니다.

- 스택: React 19 · TypeScript · Vite · React Three Fiber · drei (`ScrollControls`, `Line`)
- 전체 보기(문서형 정적 페이지): `public/quick/index.html` → 배포 후 `/quick/`

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 생성
```

## 핵심 로직 (면접에서 설명할 부분)

### 0. 도면 (`layouts.ts`의 `planLayout`)
- 1층 평면도를 막대 큐브로 그렸습니다. 조각을 빈틈없이 이어 붙이고, 선 굵기에 위계를 뒀습니다(절단 외벽 > 내벽 > 창 > 가는 선).
- 외벽(창·출입구 자리 비움), 이중선 창, 내벽, 문과 열림 궤적, 계단 챌면과 오름 화살표, 엘리베이터 X 표시, 기둥, 상부 매스 숨은선, 통심선과 통심 기호, 치수선과 틱, 방위표, 단면 표시(A-A')를 넣었습니다.
- 외곽 footprint는 01 모형과 같아서, 스크롤하면 도면의 선 조각이 그대로 모형 큐브가 됩니다.

### 1. 큐브 800개, InstancedMesh 하나
모든 장면은 `THREE.InstancedMesh` 하나로 그립니다. 큐브를 메시 800개로 만들면 draw call이 800번이지만, 인스턴싱은 한 번입니다.
장면마다 "i번째 큐브가 있어야 할 위치·크기·회전·색"을 `Float32Array`로 미리 계산해 둡니다(`layouts.ts`). 쓰지 않는 큐브는 scale 0으로 숨깁니다.

### 1-1. 매스 모형 (`layouts.ts`의 `modelLayout`)
- 0.3 모듈 큐브로 쌓은 매스 스터디 모형입니다. 재료로 역할을 나눴습니다: 저층부 발사나무, 타워 흰 보드, 판상동 연회색(유리 느낌), 별동 회색 보드.
- 큐브를 가로세로 빈틈없이 붙여 한 덩어리 면으로 읽히게 하고, 높이만 층 높이의 94%로 줄여 가는 슬래브 줄눈을 남겼습니다. 그리고 저층부 남서쪽 1층을 파내 가는 기둥만 남긴 필로티, 별동 가운데 1층을 비운 주출입구, 타워·판상동 상부 셋백을 넣었습니다.
- 모형 큐브 수(`MODEL_CUBES`)는 레이아웃에서 계산해 화면 문구에 그대로 씁니다.
- 큐브 인스턴스는 경계마다 음영 이음매가 생겨 모듈이 쪼개져 보입니다. 그래서 01 장면에 **멈춰 있는 동안만** 같은 칸들을 층·재료별로 가장 큰 직사각형으로 합친(greedy meshing) 박스(`modelSolids`, `ModelSolid.tsx`)로 바꿔 보여줍니다. 모양이 같아서 바뀌는 순간은 보이지 않고, 스크롤이 움직이면 다시 큐브로 돌아가 다음 장면으로 흩어집니다. 주변 필지도 같은 방식으로 필지당 박스 하나로 바꿉니다.

### 2. 스크롤 → 장면 보간 (`timeline.ts`, `Morph.tsx`)
- `useScroll().offset`(0~1)을 장면 번호로 바꿉니다. `s = offset × (장면 수 − 1)`.
- 각 구간의 앞뒤 25%는 **정지 구간**입니다. 글을 읽는 동안 형태가 멈춰 있도록 가운데 50%에서만 전환합니다.
- 큐브마다 지연값(`delay`)을 줘서 한꺼번에가 아니라 **아래에서 위로 쌓이듯** 움직입니다. 이동 중에는 `sin(t·π)`만큼 살짝 떠올라 조립되는 느낌을 줍니다.
- 매 프레임 `useFrame`에서 `setMatrixAt`·`setColorAt`만 호출합니다. **React 리렌더는 한 번도 일어나지 않습니다.**
  → Jabis에서 WebSocket 인식 결과 때문에 박스가 깜빡이던 문제를 풀면서 배운 방식(고빈도 값은 React 밖에서)을 그대로 적용했습니다.

### 3. 파라메트릭 파사드 (장면 2, `Mashrabiya.tsx` + `layouts.ts`의 `facadeLayout`)
- 아부다비 알 바르 타워의 마쉬라비야에서 착안한 스크린입니다. 정삼각형 모듈(한 변 0.5)을 삼각 격자로 깔고, 위가 둥근 돔 윤곽 안에 들어오는 모듈만 남겼습니다. 스크린은 원통형 타워를 감싸듯 평면에서 살짝 휘어 있습니다. (뒤쪽 유리는 두지 않았습니다)
- 모듈마다 면 3장: 모듈의 바깥 모서리가 경첩이고 꼭짓점은 무게중심(액추에이터)에서 만납니다. 로컬 좌표에서 경첩을 x축, 꼭짓점을 +y로 두고
  `이동(모서리 중점) · Y회전(곡면 접선) · Z회전(모서리 방향) · X회전(θ, 경첩)`으로 합성합니다.
  - 닫힘 θ≈4°: 3면이 거의 평평하게 맞물려 모듈을 빈틈없이 덮음
  - 열림 θ→72°: 면이 앞으로 서며 모듈 가운데에 삼각 구멍이 뚫림
- 커서를 입면 평면에 투영한 **끌개**와 모듈 중심의 거리로 열림 정도 `k = smoothstep(1 − d/R)`를 구하고, 모듈별로 lerp해 부드럽게 여닫습니다.
- 커서를 올려 두는 동안 끌개 위치에 은은한 파란 PointLight(`FacadeLight`)가 따라다니고, 커서가 멈추면 서서히 꺼집니다.
- 삼각 프레임(공유 모서리는 한 번만)은 기존 큐브 레이아웃이 담당해서, 01에서 날아오는 모듈과 이어집니다. 이 장면에서는 바닥 그림자를 끕니다.

### 3-1. 주변 맥락과 커서 반응 (`Context.tsx`, `Stage.tsx`의 `Tilt`)
- 00 도면과 01 모형은 주변 맥락을 **같은 조각으로 공유**합니다(`Context.tsx`).
  - 바닥: 0.6 모듈 타일. 도면에서는 두께 0.012의 모눈 판, 모형에서는 두께 0.18의 대지판(도로는 살짝 낮게).
  - 주변 필지: 가운데 모형과 같은 0.3 모듈 큐브. 도면에서는 보이지 않다가, 모형으로 넘어가면 한 층씩 쌓입니다. 아직 안 쌓인 층은 가로세로도 0으로 만들어 완전히 숨깁니다.
  - 나무: 솟아나기 전에는 보이지 않고, 자라면서 줄기와 수관이 함께 커집니다.
  - 주변 요소는 톤매핑을 끄고(`toneMapped={false}`) 반사율을 조명에 맞춰 보정해, 윗면이 배경색(#F3F5F4)과 같게 렌더링됩니다. 도면 단계에서는 아무것도 없다가, 솟아나는 옆면과 그림자로만 형태가 드러납니다.
  - 중심에서 멀수록 늦게 올라옵니다. 파사드로 넘어갈 때는 사라지지 않고, 가까운 모듈부터 떠올라 파사드 패널 자리(`facadeSlot`)로 날아가 크기·각도를 패널에 맞춘 뒤 패널 속으로 스며듭니다. 스크롤 진행도가 바뀌지 않으면 행렬을 다시 쓰지 않습니다.
- 모든 장면을 `Tilt` 그룹으로 감싸 커서 방향으로 살짝 기울입니다. 첫 화면 도면은 정지된 그림처럼 두려고 기울기와 카메라 패럴랙스를 모두 끄고(스크롤로만 움직임), 파사드 장면에서는 커서가 끌개 역할을 하므로 기울기를 끄고, 은하 장면에서는 천천히 스스로 돕니다.

### 4. 별만 스스로 빛나게 — 셰이더 패치
`MeshStandardMaterial.onBeforeCompile`로 프래그먼트 셰이더에 한 줄을 넣었습니다.
```glsl
totalEmissiveRadiance += vColor.rgb * uGlow;
```
인스턴스 색을 발광에 더하고, `uGlow`는 WYD 장면의 가중치에 따라 0 → 2.4로 올라갑니다. 다른 장면에서는 0이라 평범한 모형처럼 보입니다.
주의: `instanceColor` 속성이 첫 렌더 **전에** 있어야 `USE_INSTANCING_COLOR`로 컴파일됩니다(`useLayoutEffect`에서 초기화).

### 5. 카메라 (`Stage.tsx`)
장면마다 카메라 위치·시점·배경색을 정해 두고 같은 비율로 보간합니다.
데스크톱에서는 글이 왼쪽에 있으므로 카메라의 오른쪽 벡터(`시선 × up`)를 따라 카메라를 옮겨 피사체를 오른쪽에 둡니다. 모바일에서는 글 상자가 아래에 있으니 피사체를 위로 올리고 조금 멀리서 봅니다.

### 6. Jabis 로봇팔
실제 대시보드처럼 목표 각도를 **20Hz 계단식**으로 만들고, 매 프레임 `lerp(0.2)`로 따라가게 했습니다. 실제 프로젝트의 "20Hz WebSocket → 60fps 보간"을 축소해서 재현한 것입니다.

## 배포 (GitHub Pages)

1. GitHub에 새 레포를 만들고 이 폴더를 push합니다.
2. 레포 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
3. `main`에 push하면 `.github/workflows/deploy.yml`이 빌드해서 배포합니다.
   주소: `https://<아이디>.github.io/<레포이름>/`
   - 레포 이름을 `<아이디>.github.io`로 하면 `https://<아이디>.github.io/`로 바로 열립니다.
4. `vite.config.ts`의 `base: './'` 덕분에 하위 경로에서도 에셋이 깨지지 않습니다.
